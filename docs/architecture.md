# 架构与开发约定

## 目录职责

| 位置 | 职责 |
|---|---|
| 前端仓库 `src/mesh/` | 新社区页面、弹窗、会话状态和 API 封装 |
| 前端仓库 `src/router/mesh.ts` | 新前台顶层路由 |
| 前端仓库 `src/views/admin/` | 原管理后台及新增社区内容管理 |
| 前端仓库 `src/api/`、前端仓库 `src/utils/request.ts` | 原接口封装、请求与认证处理 |
| `src/main/java/com/hkuer/hkuer/controller/userface/` | HTTP 接口 |
| 同包下 `service/`、`mapper/`、`entity/` | 业务、数据库查询、请求与响应对象 |
| `src/main/resources/db/mesh/` | Flyway 版本化建表与增量迁移 |
| `scripts/` | 启动、合成演示数据和业务冒烟验证 |

新代码沿用 Controller → Service → Mapper 分层、`Result` 返回结构与现有登录上下文。新功能优先复用原服务，不绕过发帖审核、权限和数据归属判断。

## 登录与互动

1. 前端请求 RSA 公钥，加密密码后调用原 `/user/login`，后端支持用户名或邮箱登录。
2. 后端校验密码后发放 JWT，通过 HttpOnly Cookie 保存登录令牌；刷新令牌不能代替访问令牌使用。
3. 请求过滤器建立用户上下文；Service 从服务端上下文取得用户身份，不信任请求中的用户 ID。
4. 帖子点赞/收藏继续走原接口。点赞事务内更新记录与计数，首次点赞产生通知，并写入 Outbox。
5. 本地模式由 Outbox 定时处理缓存失效；RabbitMQ 链路代码仍保留，当前默认关闭监听与发送。

详见 [互动一致性实现](interaction-consistency.md)。

## 新增领域

- **问答**：回答、采纳、匿名、同问、蹲帖及不赞同；本人编辑保留 ID 与已有互动。
- **课程**：目录、参与、书签、修课评价、投票短评、资料和小组。总体评分必填，其余评分/考试信息可以不填。
- **小组**：公开招募与成员专属联系方式分离；人数和角色由服务端校验。
- **二手**：单件状态管理、图片批量发布、请求幂等与失败项重试。
- **租房**：房源、室友和求租三类信息；地区/预算/生活习惯匹配，关闭项不参与推荐。
- **消息与资料**：会话授权、消息去重和已读边界；个人资料、徽章、认证及通知。
- **管理后台**：沿用原管理员权限，增加社区内容、课程和公告管理。

## 数据边界

开发和测试使用不同 MySQL 数据库、Redis DB 和 key 前缀。Flyway 只维护当前配置指向的库，默认禁止 clean。已经应用的迁移不要改写；后续结构调整添加新的版本文件。

`V001` 至 `V012` 覆盖基础表、新社区领域及后续扩展。原业务 SQL 的必要结构已纳入迁移，不要求新使用者额外执行历史补丁 SQL。

私有配置、上传文件、验证码邮件、JWT/管理员密码和数据库备份都放在 Git 忽略的 `.local/`。源码与云凭据分离；云服务配置只通过私有配置注入。

## 验证约定

- 单元测试使用 mock 验证权限、幂等、配置选择和失败路径。
- Spring 上下文测试连接 `hkuer_mesh_test` / Redis DB 3，显式启用本地邮件和存储实现。
- `smoke-mesh*.mjs` 固定访问 9092，使用合成测试用户，不请求参考网站。
- `CloudServicesLiveTest` 默认跳过，只有显式传入 `-Dhkuer.cloud.live=true` 与配置路径才访问真实云服务。

## 已知边界

这是开发中的校园社区应用。完整真实课程数据、生产邮件/云服务凭据、支付上线、消息基础设施和全量页面状态验收应分别完成。开发模式的内容审核实现直接通过，仅供 localhost 测试；不能当作生产审核方案。
